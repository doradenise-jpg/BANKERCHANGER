## Issue #857 — Shared Types Lack Serialization Attributes

**Problem:** Some shared types were missing the `#[contracttype]` attribute
required for Soroban contract-client serialization/deserialization, causing
integration test failures when types are passed across contract boundaries.

**Fix:**
- Added new `FeeDistributionSplit` struct with `#[contracttype]` to
  `contracts/shared/src/types.rs`
- Audited every `pub struct` and `pub enum` in `types.rs` — all now carry
  `#[contracttype]`, with no gaps remaining

**Files changed:**
- `contracts/shared/src/types.rs`

## Issue #856 — Treasury Fee Distribution Splits Do Not Validate Sum

**Problem:** `set_fee_distribution` did not exist; there was no way to
configure how accumulated fees are split among multiple recipients, and no
validation that the recipient shares add up to 100 % (10 000 BPS).

**Fix:**
- Added `FeeDistributionSplit { recipient: Address, share_bps: u32 }` to
  `shared/src/types.rs`
- Added `FEE_DISTRIBUTION` persistent storage key to `treasury/src/lib.rs`
- Added `set_fee_distribution(admin, splits: Vec<FeeDistributionSplit>)`:
  - Rejects empty splits → `ContractError::InvalidFeeSplit`
  - Rejects any entry with `share_bps == 0` → `ContractError::InvalidFeeSplit`
  - Rejects total ≠ 10 000 BPS (under or over) → `ContractError::InvalidFeeSplit`
  - Emits `fee_distrib_set` event on success
- Added `get_fee_distribution()` read accessor
- Updated import in `treasury/src/lib.rs` to include `FeeDistributionSplit`

**Tests added** (`contracts/treasury/src/test.rs`):

## Issue #855 — Market Factory Whitespace Bypass in Fighter Name Validation

**Problem:** The duplicate fighter-name check compared raw byte slices without
trimming whitespace first. An attacker could bypass it by padding names:
`" Fury"` vs `"Fury"`, `"Fury "` vs `"Fury"`, etc.

**Fix:**
- Added `trim_ascii(s: &[u8]) -> &[u8]` free function that strips leading and
  trailing ASCII characters ≤ `0x20` (space) without heap allocation
- Updated the duplicate-name check in `create_market` to:
  1. Copy both fighter names into byte vecs
  2. Trim both with `trim_ascii()`
  3. Compare trimmed slices case-insensitively

**Tests added** (`contracts/market_factory/src/lib.rs` — new module
`fighter_name_whitespace_tests`):
- `test_leading_whitespace_duplicate_rejected`
- `test_trailing_whitespace_duplicate_rejected`
- `test_both_padded_case_insensitive_duplicate_rejected`
- `test_distinct_fighter_names_accepted`
- `test_distinct_padded_names_not_flagged_as_duplicate`

**Files changed:**
- `contracts/market_factory/src/lib.rs`

## Issue #854 — ALLOW_DRAW Toggle + Draw Resolution Refunds

**Problem (two parts):**

1. `set_allow_draw(false)` did not check whether draw bets had already been
   placed (`pool_draw > 0`). Disabling draw after bets were placed would
   silently lock those funds with no way to claim them.

2. If draw somehow became disabled while draw-pool bets existed and the oracle
   (or admin via `resolve_dispute`) submitted a Draw outcome, the contract
   returned `DrawNotAllowed` — permanently locking all draw-pool funds.

**Fix:**

**Part 1 — Block the toggle:**
- `set_allow_draw()` now checks `!allow_draw && state.pool_draw > 0` and
  returns `ContractError::BetsAlreadyPlaced` before touching storage.
- Enabling draw (`allow_draw = true`) is never blocked.

**Part 2 — Trigger refund on Draw-disabled outcome:**
- `resolve_market()`: when oracle reports `Outcome::Draw` with `allow_draw=false`
  and `pool_draw > 0`, set `status = Cancelled` and emit `market_cancelled`
  so all bettors can pull refunds via the existing `claim_refund` function.
  Returns `Ok(())` rather than an error so the oracle call succeeds cleanly.
  If `pool_draw == 0` the original `DrawNotAllowed` error is still returned.
- `resolve_dispute()`: identical logic for the admin dispute-resolution path.

**Tests added** (`contracts/market/src/tests.rs` — new module
`allow_draw_and_draw_resolution_tests`):
- `test_set_allow_draw_false_blocked_when_draw_bets_exist`
- `test_set_allow_draw_false_allowed_when_no_draw_bets`
- `test_set_allow_draw_true_always_allowed`
- `test_set_allow_draw_non_admin_rejected`
- `test_draw_outcome_with_disabled_draw_cancels_market_when_pool_draw_nonzero`
- `test_draw_outcome_with_disabled_draw_returns_error_when_no_draw_bets`
- `test_allow_draw_can_be_re_enabled_after_disable`
- `test_resolve_dispute_draw_with_disabled_draw_and_nonzero_pool_cancels_market`

**Files changed:**
- `contracts/market/src/lib.rs`
- `contracts/market/src/tests.rs`
